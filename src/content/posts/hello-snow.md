窗外如果刚好在下雪，请先看一会儿，再读下面这些字。

这里是一个很安静的地方：黑色的夜空、慢慢飘下来的雪，和一点点自己的想法。站点是静态的，托管在 GitHub Pages 上，成本为零，也不会忽然消失。

## 这个东西是怎么跑起来的

整站是用 [Astro](https://astro.build/) 生成的静态网页，构建后就是一堆 HTML、CSS 和一个很小的 JavaScript 文件。雪花和星星画在一张 `<canvas>` 上，用的是浏览器的 `requestAnimationFrame`，不会拖慢页面滚动。

- 写作在 Markdown 里完成，一个文件就是一篇文章
- 不需要数据库，不需要服务器，不需要登录后台
- 推送到 GitHub 之后，GitHub Actions 自动重新构建并发布

## 以后怎么加一篇文章

在 `src/content/posts/` 目录里新建一个 `.md` 文件，文件名就是网址。例如 `first-snow.md` 会变成 `/posts/first-snow/`。

文件开头那段被 `---` 包起来的部分叫 frontmatter，用来填标题和时间：

```markdown
---
title: 文章的标题
description: 一句话摘要，会显示在文章列表里
pubDate: 2026-11-15
---

正文从这里开始，用正常的 Markdown 写。
```

两个字段的规矩：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 文章标题 |
| `description` | 否 | 摘要，用于列表和分享卡片 |
| `pubDate` | 是 | 发布日期，`2026-11-15` 这种格式 |
| `updatedDate` | 否 | 修改日期，填了会在文章页显示「更新于」 |
| `draft` | 否 | 写 `true` 就不发布，草稿自己留着 |

写完保存，本地 `pnpm dev` 能立刻看到效果；提交推送之后，网站上大约一分钟就会更新。

## 想改别的地方

- 站名、简介、导航、雪的大小：`src/config.ts`
- 颜色、圆角、字号、行宽：`src/styles/global.css` 最上面的 `:root`
- 页面结构：`src/pages/` 里的文件，路径就是网址

> 改坏了也没关系。Git 记着每一次提交，随时可以退回去。
